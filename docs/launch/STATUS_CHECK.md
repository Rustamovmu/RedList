# Status check: replace the second-hand IUCN citations

**Who does this:** the owner, by hand. **Why:** every published status currently comes from Wikidata, which cites an older Red List edition (DECISIONS D-027). The coding agent may not read IUCN pages, because `iucnredlist.org` blocks it in `robots.txt`. So a person checks each species on the Red List and records what they saw, and a tool turns those rows into drafts. **Nothing in this file or the CSV was filled in by the agent.** Decision: D-032.

## What to fill in
Edit **`docs/launch/status-check.csv`** in a spreadsheet or text editor. Keep it as CSV, UTF-8, and keep the header row. The first seven columns are generated; leave them alone. For each species you check, fill in **all** of these:

| Column | What to write | Example |
|---|---|---|
| `checked_category` | The category code shown on the assessment page: `EX`, `EW`, `CR`, `EN`, `VU`, `NT`, `LC`, `DD` or `NE` | `VU` |
| `date_assessed` | The **date assessed** shown on the page, as `YYYY-MM-DD`. If the page shows only a year, leave the row empty and note it in `owner_note`: the tool never makes up a day. | `2016-06-27` |
| `trend` | The population trend as shown: `increasing`, `decreasing`, `stable` or `unknown` | `decreasing` |
| `criteria` | Optional: the criteria string, if the page shows one | `C1` |
| `assessment_url` | The address of the assessment page you read, in the form `https://www.iucnredlist.org/species/<taxon id>/<assessment id>`. The taxon ID must match the `iucn_taxon_id` column. | |
| `date_checked` | The day you looked, as `YYYY-MM-DD` | |
| `owner_note` | Optional, never imported: anything you want to remember | |

- A row with all of these columns empty is skipped ("not checked yet"). You can check a few species at a time.
- A row that is **partly** filled in stops the whole import with a message. Nothing is guessed.
- Only **global** assessments are replaced. A regional assessment stays as it is.
- The `iucn_search_url` column is a convenience search link built from the scientific name. The agent could not open it, so it is untested. The `iucn_taxon_id` values come from Wikidata (property P627), recorded in the M4 batch files.

## Then run
```
npm run status:import -- docs/launch/status-check.csv --dry-run   # check the file; writes nothing
npm run status:import -- docs/launch/status-check.csv --apply     # write the checked rows into drafts
```
- Each run writes a report in `import-reports/`.
- For each checked row, the species gets a **draft** (or its open draft is updated):
  - The global assessment is replaced by your values, with the assessment ID taken from the URL.
  - It cites a new source, "The IUCN Red List of Threatened Species: *name* (assessment *id*)", with your URL, your date checked, and the note **"IUCN Red List, checked by hand"**.
  - The status citation moves to that source.
- Re-running the same file changes nothing.
- A species whose latest revision is waiting for review is skipped; run again after review.
- **Read the report notes.** They tell you when:
  - the category changed, so the overview text may still state the old one
  - the old Wikidata source is still cited elsewhere (usually the overview)
  - a population estimate was unlinked from the replaced assessment
- Then review each draft in `/admin`, submit it and publish it. The tool never publishes.
- Rebuilding the sheet later (`npm run status:sheet`) keeps every value you filled in. A later catalogue import will not undo your change silently: the importer skips sections edited since its last run unless `--reconcile` is given.
